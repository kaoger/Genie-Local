# v6.1 手機版面（RWD）＋客戶名單分類標籤 — 規格

> 狀態：**定稿**（2026-09-30；Claude 起草 → Codex 正方＋Grok 反方〔含 iOS Safari 網路查證〕→ Claude 裁決 → 使用者決定「切換：只顯示那一區」）。
> 使用者要求：①網站要做 RWD；②手機版客戶名單要往下拉才看得到「已回報」，希望有分類標籤迅速到相關卡片。

## A. 客戶名單分類標籤（`leads.js` 為主）
1. 名單頂部加**分頁切換標籤**：`待聯絡 N`、`已回報 N`（`role="tablist"`／`role="tab"`／`aria-selected`）。**一次只顯示一區**；預設「待聯絡」。電腦與手機同一套行為。焦點留在按下的標籤；切換不捲動、不改網址（`#/leads` 為完全比對，不可用 `<a href="#…">`）。
2. 切換時畫面回到該區頂端（對 `main` 設 `scrollTop=0`，不用 `scrollIntoView` smooth）。
3. **數字＝資料庫總數**：各區第一頁查詢改 `select(columns, { count: 'exact' })`，讀 `response.count`；**只在 offset 0 寫入**，「載入更多」不覆寫。`count` 非有限數字→顯示「—」；離線顯示「—」；**讀取中保留上一次數字**（不閃成「—」）。總數與已載入張數不同屬正常（保留「載入更多」）。
4. 「已回報」區內加**結果篩選晶片**，順序與卡片結果鈕一致：全部／已聯絡／約丈量／沒興趣／聯絡不上。
   - 伺服器端篩選：「全部」維持 `contact_result not is null`；其他加 `contact_result = 值`；切換晶片重置該區分頁。
   - **頂部「已回報 N」永遠是全部已回報總數**；目前選中的晶片旁顯示該篩選的數量（取自該次列表查詢的 count）；其他晶片不顯示數量（不另發 count 查詢）。
   - 篩選後 0 筆：顯示「目前篩選沒有資料」（不是「還沒有已回報的客戶」）。
5. 篩選與目前分頁只存記憶體：整頁重新載入回到「待聯絡／全部」；頁內「重新整理」與回到前景（`visibilitychange`，含從電話／Messenger 回來）**保留**目前分頁與晶片。
6. 在待聯絡回報結果後：卡片離開待聯絡、兩個數字更新；若目前已回報篩選與結果不符，toast 顯示「已記錄為〇〇（目前篩選未顯示）」且**保留既有「收回」動作**。
7. 版面：標籤列放在 `main` 內；若 sticky 不可再包一層 `overflow` 容器。離線橫幅高度不可寫死（手機會換行），`main` 上方留白依實際高度。手機底部預留 toast 高度，避免蓋住最後一張卡的結果鈕。

## B. 首頁專案清單改卡片（`app.js` `render()`、`styles.css`）
1. 寬度 **≤ 900px**（既有斷點，含 iPhone 橫向）顯示**另外輸出的卡片標記**；> 900px 維持現有表格。兩者由同一份資料在 `render()` 產生，CSS 依寬度只顯示其一；不在表格上用 `display:block` 硬轉（Safari／VoiceOver 不穩）。
2. 卡片內容：名稱（＋示範標籤）、聯絡人、洽詢日期、需求來源、目前步驟、操作（開啟／複製／刪除）、選取勾選框。需求類型、信箱、電話、到期日在卡片不顯示（進專案可看）。「範例」展示列在卡片模式改成一句說明，不做成假客戶卡。
3. 保留分頁、全選（卡片模式在清單上方另放「全選本頁」）、批次刪除與復原。整張卡可點進專案（勾選框、步驟連結、操作鈕除外，各自獨立可點）。卡片沿用 `data-id`、`data-select`、`data-copy`、`data-delete`。
4. 卡片模式勾選框、操作鈕點擊區 ≥ 44×44px。

## C. 整站手機巡檢與修正
頁面：登入、首頁、專案內頁六步驟（含策略企劃 AI 流程）、側邊表單（drawer）、估價、提案預覽、客戶名單、各對話框。
1. 375×812 不可整頁橫向捲動（量 `main` 捲動容器與 `documentElement`，容許 1px）；估價明細表可在 `.estimate-scroll` 內橫向捲動。
2. 主要操作點擊區 ≥ 44×44px（含側欄按鈕、登出、分頁鈕）。
3. **手機寬度輸入框（input／select／textarea）字級 ≥ 16px**，避免 iOS 聚焦自動放大；**不可**在 viewport 加 `maximum-scale`／`user-scalable=no`。
4. **不加** `viewport-fit=cover`（本版不處理瀏海安全區；加了就必須全站補 inset）。
5. 左側窄欄維持（底部導覽列列入下一版）：側欄 `overflow-y:auto`、按鈕 44px、iPhone 橫向（高度約 390px）時按鈕不互相重疊；離線橫幅的 `left` 跟著欄寬。
6. 沿用 900／600px 斷點；不加 CSS 框架、不加套件。
7. iOS 鍵盤開啟時底部固定元素（toast）可能被蓋：本版只做實機檢查並記錄，不追加修正。

## D. 測試
- Playwright（Chromium）：375×812、768×1024、1280×800 巡檢 C 的頁面寬度；手機寬度輸入框 computed `font-size >= 16px`；側欄按鈕尺寸。
- 名單 mock 補 `Content-Range`（如 `0-49/51`）與 `count`：斷言標籤數字＝總數（非頁數）；切換只顯示一區；晶片請求帶 `contact_result=eq.site_visit` 且**畫面只剩該結果**（mock 需依參數真的過濾）；「全部」仍帶 `not.is.null`；篩選後 0 筆文案；載入更多不覆寫數字；重新整理／回前景保留分頁與晶片；回報不符篩選的提示保留收回；離線顯示「—」；離線橫幅換行時不遮內容。
- 首頁：≤900 顯示卡片、>900 顯示表格；卡片勾選／全選本頁／批次刪除／復原／分頁；整卡點擊進專案、按鈕不誤觸；示範標籤；範例列不成卡。既有依 `tr[data-id]` 的測試改用可同時涵蓋兩種模式的選擇器。
- **iPhone 實機驗收（使用者）**：名單切換與篩選、登入、drawer 表單、估價、策略貼上，各走一次；檢查不自動放大、無橫向捲動、按鈕好按、橫向可用。

## E. 範圍外
底部導覽列、`viewport-fit=cover` 與安全區、捲動跳轉與捲動高亮、晶片各自數量、iOS 鍵盤遮擋修正、視覺重新設計、深色模式、PWA。

## G. 兩方採納紀錄
- **Codex 採納**：數字用第一頁 `count:'exact'`、載入更多不重算、「已回報 N」維持全部總數＋選中晶片顯示篩選數、晶片不各自計數、左側窄欄維持、離線橫幅高度不寫死、mock 補 `Content-Range`、加測載入更多後切篩選與離線橫幅換行、實機驗收。
- **Grok 採納**：只顯示一區的分頁切換（使用者選定；iOS 非 body 捲動容器的程式捲動有 WebKit 已知問題）、不改網址、只在 offset 0 寫數字且讀取中保留舊數字、「全部」維持 `not is null`、晶片順序同結果鈕、篩選 0 筆文案、回前景保留篩選、提示保留收回、toast 遮最後一張卡、斷點用既有 900（含橫向）、另寫卡片標記不硬轉表格、範例列不成假卡、熱區 44px、輸入框 16px 且不鎖縮放、不加 `viewport-fit=cover`、側欄可捲、mock 依參數真過濾、量 `main` 捲動容器。
- **未採納**：Codex「捲動跳轉」（使用者選切換）、Codex「卡片斷點 600」與「CSS 轉表格」（改 900、另寫卡片）、Grok「篩選時頂部標籤改顯示篩選後數量」（改為頂部永遠總數、晶片旁顯示篩選數，語意較穩定）。
