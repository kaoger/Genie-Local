# v8.1 Web App（加入主畫面、全螢幕）— 規格（定稿）

## 0. 目標
- 使用者 2026-10-01：手機要「像一個 App」。iPhone Safari →「分享 → 加入主畫面」後，主畫面有圖示，點開是全螢幕（沒有 Safari 網址列與工具列）。
- 前提：v8 已上線（專案存雲端），Web App 與 Safari 儲存空間分開也不會看不到專案；第一次開 Web App 要重新登入。
- 範圍外：上架 App Store／Play、推播通知、Service Worker 離線快取、背景同步。

## 1. Manifest 與圖示
- 新增 `assets/manifest.webmanifest`（放在已允許的 `/assets/`，免改 nginx 白名單；確認 MIME 為 `application/manifest+json`，不是就於 nginx 補 types）：
  - `name`、`short_name`（主畫面顯示名，≤6 個中文字，使用者決定）
  - `start_url: "/#/"`、`scope: "/"`、`display: "standalone"`、`orientation` 不鎖
  - `background_color`、`theme_color`（沿用現有白底黑字）
  - `icons`：192、512（`purpose: "any"`）＋ 512 maskable
- `index.html` head：`<link rel="manifest">`、`apple-touch-icon`（180×180 PNG）、`apple-mobile-web-app-capable=yes`（舊版相容）、`apple-mobile-web-app-title`、`apple-mobile-web-app-status-bar-style`（討論題）、`theme-color`。
- 圖示由使用者提供或以簡單字標產生（討論題）；PNG 放 `assets/icons/`，不引入任何套件。

## 2. 全螢幕版面（`viewport-fit=cover`）
- viewport 改為 `width=device-width, initial-scale=1, viewport-fit=cover`。
- 安全區：
  - 頂部：v7.3 頁首已有 `padding-top: env(safe-area-inset-top)`；專案詳細頁頂端（`.detail-header`）、抽屜、對話框、離線橫幅也要避開瀏海／動態島。
  - 底部：v7.2 底部列已有 `env(safe-area-inset-bottom)`；確認 toast、回到頂部、更多選單、抽屜底部按鈕。
  - 左右：橫拿時瀏海在側邊，底部列、頁首、內容要加 `env(safe-area-inset-left/right)`。
- 電腦版不受影響（桌機 env() 為 0）。

## 3. Standalone 模式的行為差異
- **沒有瀏覽器返回鍵**：專案詳細頁手機版目前把麵包屑隱藏（`styles.css` `.crumbs>a{display:none}`），只能靠底部列回清單——是否加返回鍵（討論題）。
- **沒有下拉重新整理**：專案靠 v8 回到前景自動同步；名單頁有「重新整理」。是否需要其他重新整理入口（討論題）。
- **外部連結**：Messenger（`m.me`）、電話（`tel:`）在 standalone 要能正常開 App／撥號，不可卡在 Web App 內。
- **登入**：Web App 第一次要登入；`supabase-js` `detectSessionInUrl:false` 不變；登出照 v8（先確認上傳再清）。
- 使用說明加「加入主畫面」步驟（iPhone Safari：分享 → 加入主畫面；Android Chrome：選單 → 安裝應用程式）。

## 4. 不做
- Service Worker（避免舊版快取卡住更新、與 v8 同步衝突）。
- 自訂安裝提示橫幅（iOS 不支援 `beforeinstallprompt`）。

## 5. 驗收
- Playwright：manifest 200、JSON 欄位、icon URL 解析與實際尺寸（`naturalWidth`）；head 標籤；未註冊 Service Worker；以正式安全區變數注入上 59／下 34／左右 59px 驗證可點擊座標（375×812、844×390 左右兩向、768×1024、1280×800；登入、清單、名單、詳細頁、換行橫幅、toast、抽屜、策略對話框）；直接進詳細頁後「返回潛在客戶」可用（含唯讀分頁）；桌機外觀不變；既有全套連跑 2 次全過。
- 外部檢查（Claude）：上線後 `/assets/manifest.webmanifest`、圖示 200、MIME 正確、CSP 不擋。
- iPhone 實測（使用者）：加入主畫面 → 圖示與名稱正確 → 全螢幕開啟 → 登入 → 專案從雲端出現 → 直拿／橫拿瀏海與底部橫條不擋任何按鈕 → Messenger、電話按鈕能跳出 → 登出正常。

## 6. 裁決（Codex 正方＋Grok 反方一致，Claude 定稿）
1. **名稱與圖示（使用者決定）**：`short_name`／`apple-mobile-web-app-title`＝「三禾」，`name`＝「三禾工作台」。圖示先用黑底白字「三禾」字標，不引入任何套件（例如 Windows 內建 .NET `System.Drawing` 產生 PNG，記錄字型與參數）。檔案：`assets/icons/icon-180.png`（apple-touch-icon）、`icon-192.png`、`icon-512.png`（purpose any，不透明黑底）、`icon-512-maskable.png`（文字在中央 80% 安全圓內）。本版例外允許新增這些 `assets/` 檔案。之後換 logo 時換檔名。
2. **狀態列**：`default`（不用 `black-translucent`）。仍加 `viewport-fit=cover`，但 inset 為 0 時版面不可壞。
3. **返回鍵**：要做。手機版（`(max-width:600px), (max-height:500px)`）專案詳細頁顯示 ≥44×44「返回潛在客戶」，直接到 `#/`（不用 `history.back()`）；唯讀分頁也可用。
4. **重新整理**：不新增；使用說明寫「專案：點清單上方同步狀態；名單：按重新整理」。
5. **Service Worker**：不做（本版不增加離線快取與更新管理；不保證斷網冷啟動）。
6. **nginx**：manifest 放 `/assets/manifest.webmanifest`。**不可**在 server 內新開 `types {}`（會蓋掉整份 mime.types）；改用 `location = /assets/manifest.webmanifest { default_type application/manifest+json; ... }` 或等效寫法。manifest 快取改 `no-cache`：在既有 `map $uri $genie_cache_control` 加一條，**不要**在 location 內另寫 `add_header`（nginx 1.27 會不再繼承上層 CSP 等標頭）。CSP 明列 `manifest-src 'self'`。部署需 `nginx -t` 並重建容器。

## 6.1 定稿補充
- manifest 固定 `id: "/"`；icons 補 `type: "image/png"`，URL 用絕對路徑 `/assets/icons/...`。
- `apple-mobile-web-app-capable=yes` 保留（iOS 16.4–18 後備）。
- **安全區四向**：集中定義變數；最上層可見元件負責頂部 inset（離線橫幅出現時由它負責，頁首不重複加）；涵蓋登入殼層（第一屏）、`.detail-header`、抽屜頭尾、對話框（含策略滿版對話框）、toast、回到頂部、更多選單、底部列；橫拿左右兩個方向都要。麵包屑隱藏條件改用手機版媒體條件（目前只看寬度，844×390 會顯示麵包屑）。
- **外部連結**：Messenger 維持現行「開 Business 收件匣＋複製姓名」流程（不改成 m.me），保留點擊當下同步 `window.open`；電話維持 `<a href="tel:">`。驗收接受「能完成外部操作並回到工作台」，原生 App 跳轉以實機為準。
- **匯出**：standalone 可能無法下載；使用說明加「若主畫面 App 無法儲存備份，請改用 Safari 打開網站匯出」。
- **使用說明**：iPhone：Safari → 分享 → 加入主畫面，**保持「以 Web App 開啟」開啟**；Android Chrome：選單 → 安裝應用程式／加入主畫面。提醒：先確認 Safari 清單顯示「已同步」再改用主畫面 App；筆記、本機顯示名稱、未儲存內容不會帶過去；第一次要登入。標題改掉「v8」字樣。

## 7. 預估
Codex 實作＋測試約 2.5–3.5 小時；部署檢查 15 分鐘；使用者 iPhone 實測 15 分鐘。
