# v7.1 名單帶入改善（坪數區間、專案名稱、聯絡時段）— 規格

> 狀態：**定稿**（2026-10-01；Claude 草案 → Codex 正方＋Grok 反方 → Claude 裁決；三個待討論點兩方結論一致）。
> 使用者 v7 實測回饋並選定：①新增「坪數區間」欄；②專案名稱改「高旭陽｜高雄 新成屋 20 坪以下」；③聯絡時間要有能直接帶入的欄位。

## 1. 坪數區間
- **居家（房屋概況）與商空／展覽（共用場地區塊）**新增 `areaRange`「坪數區間」（select），放在「坪數」旁，選項與機器人表單逐字相同：20 坪以下／21–30 坪／31–40 坪／41–60 坪／61 坪以上／尚未確定（破折號為 `–`）。**不標** `ai:true`、**不標** `est:true`。
- 從名單建立：類型看得到此欄且 `size` 與選項逐字相同 → 填 `brief.areaRange`，不寫 `needsNote`；對不上的原文、或類型為其他設計（無此欄）→ 仍寫 `needsNote`。
- **確認需求（只改 `readiness`）**：「坪數」那一格在「精確坪數 > 0」**或**「區間為前五個選項之一」時算齊；**「尚未確定」不算**。居家必填分母仍為 4。缺項標籤寫「坪數或坪數區間」；區間為尚未確定時狀態寫「坪數區間為尚未確定，請改選或填精確坪數」。精確坪數的 `ai:true` 保留（視覺發想依據不變）。已確認且精確坪數 > 0 的舊案不強迫補區間。
- **AI 策略**：`STRATEGY_FIELDS` 的 home 與 space 都在 `area` 後加入 `areaRange`；兩行都送（沒有值寫「未填」），精確在前、區間在後。欄位定義與白名單必須涵蓋同一批類型（居家＋商空＋展覽），`strategyPrompt` 找不到欄位定義時不得讀 `.label` 丟例外。
- **業務估價**：「室內設計費（沿用需求坪數）」列仍只用精確坪數；沒有精確坪數時在該列提示「需求沒有精確坪數，數量是 0。目前只有區間：21–30 坪。填了精確坪數才會帶入。」不另加阻擋規則，不從區間推算。只改區間不得讓估價需更新。
- **舊資料**：不自動搬移 `needsNote` 的「坪數（客人勾選）」；缺坪數且其他需求有該句時提示「其他需求裡的區間不會算進新欄位，請在坪數區間重選一次」。`areaRange` 缺少、null、數字、不在選項：保留原值、不 throw、不寫回。

## 2. 舊完成依據相容（必做）
- 新欄位會讓 `reqOf`（需求依據）與策略快照多一鍵；舊 `steps.brief.basis.req`、`steps.strategy.basis`（含提案巢狀依據與策略目前版／上一版／待回覆／比較的 snapshot）缺此鍵會被誤判需更新。
- 載入時在 `normalizeProject` 的逐筆隔離流程內、**只在記憶體**替缺少 `areaRange` 鍵的舊依據與快照補 `areaRange:''`（鍵已存在就不動）；不重建、不改完成時間、**載入時不 `save()`**。
- 驗收：六步驟皆已完成的舊案，升級後六步仍全是「已完成」，localStorage 一字未改；真正改了區間後需求與策略才需更新。
- **驗收修正（Grok 複查）**：補鍵只限該類型需要的依據——需求依據看 `reqOf` 是否含 `areaRange`、策略依據／快照（含比較清單）看 `strategyFields(快照自身類型)`；品牌、包裝、網站、其他設計不補。異常資料（`brief.areaRange` 已有非空值但依據缺鍵，正常升級不會出現）依據改用目前值正規化後補上，維持原狀態（Claude 裁決接受，與「補空值」的偏差僅限此情況）。編輯儲存時未改動區間就保留原值（含 null、數字、物件）。

## 3. 專案名稱
- 從名單建立的名稱：`姓名｜地區短名 服務短名 坪數區間`（全形 `｜`），例：`高旭陽｜高雄 新成屋 20 坪以下`。去空段；最長 80 字；姓名空白→「未留姓名」。
- 地區短名：已辨識縣市去尾「市／縣」，但**新竹市／新竹縣、嘉義市／嘉義縣保留全名**；嘉義（未辨識）與對不上的自由文字用原文。
- 服務短名（與欄位用詞一致）：新成屋裝潢→新成屋；舊屋翻新→老屋翻新；局部裝修→局部翻修；商業空間→商業空間；其他服務→其他；未知字串→原文。
- 坪數為「尚未確定」、空白或對不上時省略。
- 只影響新建立的專案；來源卡加一句「名稱是建立當下的簡稱，縣市欄位是全名，之後都不會跟著名單改」。

## 4. 聯絡時段
- 既有 `brief.contactTime`（多選）選項：**前面加入**上午 8–12 點／下午 1–5 點／晚上 6–9 點，後面保留平日白天／平日晚上／週末／隨時。欄位下說明：「時段有重疊，帶入客人勾的即可，不必再勾平日白天／晚上。」
- 從名單建立：`contact_time` 與三個選項逐字相同 → `brief.contactTime=['上午 8–12 點']`，不寫 `notes`；否則仍寫 `notes`。
- 不送 AI（白名單不變），不進需求完成依據。

## 5. 來源卡與測試
- 來源卡依**實際寫入位置**列示（`areaRange` 有值→已寫入「坪數區間」；`contactTime` 有值→已寫入「方便聯絡」；只有舊 `needsNote`／`notes` 句子時才列其他需求／備註）。名單較新提示仍比八欄 digest，不自動改名稱與欄位。
- 複製專案保留 `areaRange`、`contactTime`，照舊清 `leadId`、`leadDigest`。
- 測試：改寫 `tests/v7-leads.spec.js` 中與本規格相反的舊斷言；新增——區間帶入與對不上時去向、其他設計不產生 `areaRange`、「尚未確定」不能確認、精確或區間擇一可確認、AI 指令兩行（含只有區間）、展覽類型策略不丟例外、估價 0 坪提示且只改區間不讓估價需更新、名稱格式（各縣市含新竹／嘉義、各服務、未知服務、尚未確定、無姓名）、聯絡時段帶入與對不上、六步已完成舊案升級後仍全完成且 localStorage 不變、壞資料仍逐筆隔離不寫回、手機 375／844。
