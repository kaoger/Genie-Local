# v7.2 手機底部導覽列（圖示加文字）— 規格（定稿）

## 0. 問題
使用者 2026-09-30 iPhone 實測：手機左側窄欄只有圖示、沒有文字，看不出哪個是首頁（資料夾＝潛在客戶）。窄欄還吃掉約 15% 寬度。

## 1. 範圍
- **手機（直拿與橫拿）改成底部導覽列**：媒體條件 `(max-width:600px), (max-height:500px)`（以下稱「手機版」）。使用者 2026-10-01 決定橫拿也放底部，方便點。
- 其他寬度（電腦、iPad）維持現有左側欄，外觀與順序不變。
- 改 `index.html`、`styles.css`、`app.js`、`tests/**`。不改資料格式、localStorage 結構、登入流程。

## 2. 底部導覽列（四格，使用者選）
- 手機版時左側欄改成固定在畫面底部的一列，`main` 不再留左邊距。
- 四格，每格**圖示＋文字**（文字 ≥12px，永遠看得到）：
  1. **潛在客戶**（`home`，資料夾）
  2. **客戶名單**（`leads`）
  3. **新增**（`add`）：只有**圖示外圍**保留黑色小圓，文字在下面；整格與其他格同高、不凸起。
  4. **更多**（新按鈕）：打開選單，依序為「知識庫」「個人設定」「匯出本機資料」「使用說明」「登出」。
- **可見文字、`aria-label`、`title` 三者一致**（例如都是「潛在客戶」「客戶名單」），新增格維持「新增專案」為 `aria-label` 時可見字寫「新增」—允許，但不得出現與頁首不同的頁名。
- `aria-current="page"` **只用在「潛在客戶」「客戶名單」**（沿用 `app.js:663-664`，專案詳細頁仍標潛在客戶）。「更多」用 `aria-expanded`／`aria-controls`。
- 每格點擊範圍 ≥44×44px。頂端大頭貼在手機版隱藏（功能在「更多 → 個人設定」）。
- **同一組按鈕**：沿用既有 `data-action` 按鈕，不複製第二組導覽；手機版把「知識庫／個人設定／匯出／說明／登出」放進「更多」選單的呈現方式由實作決定（可移動 DOM 節點或用同一組按鈕切換顯示），但同一功能在畫面上只能有一顆可見按鈕，且鍵盤 Tab 順序與畫面順序一致。
- **圖示注入**：`app.js:7` 目前對 `[data-icon]` 整個覆寫 `innerHTML`，會清掉文字。改為導覽按鈕注入圖示時保留文字標籤；其他共用 `data-icon` 的按鈕（分頁、關閉鈕等）行為不變。
- 不改 `viewport-fit`；底部列 `padding-bottom` 可加 `env(safe-area-inset-bottom, 0px)`（無害）。是否被 Safari 網址列或首頁橫條擋住，以使用者 iPhone 實測為準。

## 3. 「更多」選單
- 從底部列上方彈出；每項 ≥44px 高、圖示＋文字。
- 點選單外、按 Esc、再按「更多」都會關閉；關閉後焦點回到「更多」。
- 點「個人設定」「知識庫」「使用說明」：**先關選單，再開對話框**；對話框關閉後焦點回到「更多」。
- 登出：維持現在按了就登出（不加確認；名單頁頂端的登出鈕也不變）。
- 登出、權限失效、未登入時選單與底部列都要消失；視窗變成非手機版時選單自動收起。

## 4. 不可被底部列擋住
- 用**一個**共用的底部留白值（底部列高度＋安全區＋少量間距）取代手機版目前 110／120／150px 三個值，套用在首頁清單、名單、專案詳細頁；最後一張卡片／分頁按鈕／詳細頁底部都能捲到底部列上方。
- `#toast` 在手機版置中，位置在底部列上方，不壓住「新增」。
- 離線橫幅在手機版貼齊左邊（`styles.css` 有兩處 `left:57px`，都要改）。
- 抽屜與對話框用 `showModal()` 本來就在最上層，不需為底部列另加留白。
- 鍵盤跳出時**不隱藏**底部列（第一版不做鍵盤偵測）；以 iPhone 實測確認輸入框不被擋。
- 名單分類標籤（v6.1）位置不變。

## 5. 文字更新
- 使用說明與「讀取失敗請先匯出」的提示不可只寫「左側」；改成桌機、手機都適用（例如「左側欄或手機底部『更多』裡的『匯出本機資料』」）。

## 6. 驗收
**Playwright（375×812、600×900、844×390 為手機版；768×1024、1280×800 為左側欄）：**
1. 手機版四格文字可見、≥12px、與 `aria-label` 一致；每格 ≥44×44。
2. 潛在客戶↔客戶名單切換、專案詳細頁、瀏覽器返回時 `aria-current` 正確。
3. 「更多」開關（點外、Esc、再按）、焦點回到「更多」；五項皆可用（匯出下載格式不變、個人設定可存、說明可開關）。
4. 手機版↔左側欄切換時選單收起、不殘留；左側欄外觀與按鈕順序不變。
5. 清單、名單、六步驟頁最後內容與 toast 在底部列上方；整頁無橫向捲動（估價表自身的橫向捲動除外）。
6. 未登入／登出後底部列與選單不見。
- 既有測試依新操作更新後全部通過（例如手機匯出改成先開「更多」、375px 側欄可捲的斷言改寫）。不寫死測試數量。

**iPhone 實測（使用者）：** 直拿、橫拿各一次：底部列沒被 Safari 網址列或橫條擋住；點輸入框時鍵盤不擋輸入；更多選單好按。

## 7. 預估
Codex 實作＋測試約 2 小時。

## 8. 兩方採納紀錄
- **使用者決定**：四格（知識庫收進更多）；手機橫拿也用底部列。電腦／iPad 不變。
- **一致**：同一組按鈕、`aria-current` 只給兩個頁面、圖示注入會清掉文字要改、登出不加確認（原規格「維持確認」是錯誤前提）、不寫死測試數、Chromium 不能代替 iPhone、對話框先關選單再開。
- **Grok 採納**：可見字用頁名「潛在客戶」「客戶名單」並與 aria-label 一致；新增不凸起；鍵盤時不隱藏、只留捲動空間；單一底部留白值；toast 不壓新增；橫幅兩處 57px；不改 viewport-fit。
- **Codex 採納**：更多用 aria-expanded；跨尺寸收起選單；登出／失效清除；更新說明文字；分類標籤不動；黑圓保留（Claude 折衷：只圈圖示）。
