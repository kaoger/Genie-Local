# v9 流程待辦核心（分支自動化執行層）— 規格（草稿，待 Codex 正方＋Grok 反方）

## 0. 目標與範圍
- 使用者 2026-10-07：想要「事件發生後的標準流程」，例如約丈量之後一整套步驟，依結果走不同分支。先做**核心執行層**；各分支的實際步驟與天數之後再由使用者定（本版用範例流程測試）。
- 架構決定（使用者同意）：**核心放在現有 Supabase**（資料表＋資料庫函式＋pg_cron＋Edge Function）。**n8n 不用在核心**，日後只做周邊（待辦建立時丟 LINE／Google 日曆）。
- 原則（沿用架構評估三方共識）：系統只做**內部動作**（建待辦、算到期、提醒、顯示下一步）；**每一步的結果由人選**；**不自動傳訊息給客人**（Meta 24 小時窗與送審承諾）；不讓 AI 判斷結果。
- 範圍外：拖拉式流程編輯器、自動對客人發訊、AI 判斷、統計報表（v9.2 以後）、n8n／LINE／日曆串接（v9.3 以後）。

## 1. 概念
- **流程範本（playbook）**：每個「分支起點」（例如 `contact_result = site_visit` 約丈量）對應一串步驟；每一步定義：`step_key`、顯示名稱、到期規則（相對事件或上一步完成的天數／小時、或「指定日期」如丈量日）、可選結果清單、每個結果接到哪一步（或結案）。
- **待辦（task）**：某位客人（名單 `customer_leads.id`）的某一步，一筆一列。
- **事件**：
  1. 聯絡結果被設定／更改（Genie 名單按鈕、日後信件連結）→ 依結果啟動對應分支的第一步。
  2. 15 分鐘內收回聯絡結果 → 取消該分支尚未完成的待辦。
  3. 人把某一步標「完成」並選結果 → 依範本建立下一步（或結案）。
  4. 人「跳過」或「改期」某一步。

## 2. 資料（Supabase，SQL 放 `ops/`，使用者在 SQL Editor 執行或 Claude 經授權執行）
- `public.lead_tasks`：`id uuid pk`、`lead_id uuid → customer_leads.id`、`playbook_version int`、`step_key text`、`occurrence int`（同一步第幾次，例如改期重來）、`status`（`open`／`done`／`skipped`／`cancelled`）、`due_at timestamptz`、`outcome text`、`note text`、`assignee uuid null`（討論題）、`created_at`、`completed_at`、`completed_by uuid`、`reminded_at`（v9.1）、`version int`（樂觀鎖）。
- 唯一鍵 `(lead_id, step_key, occurrence)`：同一事件重送不會重複建。
- 範本存放（討論題）：資料表 `lead_playbook_steps`（由 repo 內的 SQL 種子檔建立、帶版本）或 repo 內 JSON。
- 權限：RLS 只給啟用成員讀；寫入**只走 RPC**（`genie_complete_task`、`genie_skip_task`、`genie_reschedule_task`），比照 v8 `genie_projects`；anon 全拒；service_role 依需要最小授權。
- 觸發：`customer_leads` 的 `contact_result` 更新時（AFTER UPDATE，只看這一欄變化）在同一交易建立／取消待辦。**不加 INSERT 觸發器、不改機器人程式**；機器人寫入名單的路徑不受影響。

## 3. 畫面（Genie）
- 名單卡片與專案頁：顯示「下一步：○○，到期 10/9」（逾期用 v8.2 顏色）。
- 待辦操作：完成（選結果＋可填備註）／跳過／改期；結果按鈕由範本決定。
- 「今日待辦」：列出今天到期與已逾期的待辦（可與 v8.2 待聯絡摘要整合，討論題）。
- 手機版沿用 v7.2／v7.3／v8.1 版面規則。

## 4. 分階段
- **v9.0**：資料表＋範本＋觸發＋三支 RPC＋畫面顯示與操作（**不寄提醒**）。用範例流程（約丈量 3 步、已聯絡 2 步）驗收。
- **v9.1**：到期提醒——pg_cron 每 15 分鐘掃 `due_at <= now() and status='open' and reminded_at is null`，以 claim 原子搶單，呼叫 Edge Function 經 Resend 寄信給成員；每筆只提醒一次；失敗可重試、結果不明不重寄（比照 notify-lead 的 claim 模式）。提醒時段（例如只在台北 8:00–21:00 寄）討論題。
- **v9.2**：統計（哪步最常卡、沒成交原因）。
- **v9.3**：n8n 周邊（待辦建立時丟 LINE／日曆），以 Database Webhook 或輪詢 `lead_tasks` 實作，不改核心。

## 5. 與既有功能的關係
- v5 聯絡結果與 15 分鐘收回：觸發器需處理「收回」把 `contact_result` 改回 null 的情況。
- v7 名單建立專案：待辦掛在**名單**（客人）上，不掛專案；專案頁顯示該客人的待辦。
- v8.2 待聯絡分級：待聯絡（尚未回報）仍由 v8.2 呈現；v9 處理回報之後的流程。
- 機器人 FB 審核中：不改客人看得到的流程、不推 VPS-message main；本版只動 Genie 與資料庫。

## 6. 驗收（v9.0）
- SQL 驗收腳本（比照 `genie-projects-verify.sql`）：anon／非成員／停用成員全拒；成員只能經 RPC 寫；同事件重送不重複；收回會取消；完成走對分支；樂觀鎖衝突。
- Playwright：各分支走一遍、改期、跳過、收回、逾期顏色、手機版、XSS；既有全套連跑 2 次全過。
- 使用者實測：對一位測試名單按「約丈量」→ 看到下一步 → 完成並選結果 → 看到下一步改變。
