# v8.1.1 頂部提示條修正 — 規格（定稿）

## 0. 問題（Grok 於 v8.1 實作複查提出、Claude 當時接受延後，使用者 2026-10-07 選做）
- 唯讀提示條 `#sync-readonly`（「此分頁只能查看…」）與儲存警告 `#storage-warning` 排在頁首前（`index.html` 約 40–41 行），但頂部安全區只加在 `.page-header`／`.detail-header`。
- 唯讀或儲存警告是畫面最上層時：直拿會鑽進瀏海／動態島，橫拿左右沒避開。
- 離線橫幅（`.offline-banner`，fixed）出現時，v8.1 把 `main` 的 `padding-top` 清成 0、只給頁首 `margin-top`，這兩條提示會被壓在橫幅底下。

## 1. 要求
- 「最上層可見元件負責頂部安全區」：依序可能是 離線橫幅 → 唯讀條／儲存警告 → 頁首。只有最上面那個加 `env(safe-area-inset-top)`，下面的不重複加。
- 離線橫幅出現時，唯讀條、儲存警告、頁首都排在橫幅下緣之後，不被遮住、不重疊。
- 唯讀條與儲存警告在橫拿時左右避開安全區（沿用 v8.1 的 `--safe-left`／`--safe-right` 或等效變數）。
- 只改版面（CSS 為主，必要時少量 JS 調整類別）；不改同步邏輯、文案、資料。
- 電腦、iPad、無安全區時外觀不變。

## 2. 驗收（Playwright）
- 375×812、844×390（左右瀏海）、768×1024、1280×800；以 v8.1 測試的安全區注入方式（上 59、下 34、左右 59）。
- 組合：只有唯讀條；只有儲存警告；兩者同時；再各自加上離線橫幅（含橫幅換行）。每個組合在清單頁、名單頁、專案詳細頁檢查：提示條上緣 ≥ 安全區或橫幅下緣、彼此不重疊、頁首在它們下面、按鈕可點、無橫向捲動。
- 既有全套連跑 2 次全過。
- 使用者 iPhone 實測（可選）：同時開兩個分頁讓其中一個變唯讀，看黃條沒被瀏海擋住。

## 3. 範圍
改 `styles.css`、必要時 `app.js`／`index.html`、`tests/**`。預估 Codex 30–60 分鐘。

## 4. 已知限制（Grok 複查，Claude 接受）
- 有唯讀條／儲存警告、無離線橫幅時往下捲，sticky 頁首不再帶頂部安全區（`--header-safe-top` 為 0）。唯讀條只在同瀏覽器雙分頁出現，主畫面 App 為單一實例碰不到；一般 Safari 直拿時安全區為 0；剩儲存警告＋主畫面 App＋捲動的罕見組合。日後若要修：提示條一併 sticky，或頁首黏住時另補安全區。
