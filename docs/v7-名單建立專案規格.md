# v7 客戶名單一鍵建立專案 — 規格

> 狀態：**定稿**（2026-09-30；Claude 草案 → Codex 正方＋Grok 反方 → Claude 裁決 → 使用者決定「要提醒名單較新」）。
> 使用者選定：客人 Messenger 填表 → 名單卡片按鈕 → 自動帶入 → 進專案補需求 → 策略企劃，不用重打。
> **推翻 v5 §1／§9.4「建立專案延到專案進資料庫」**：使用者接受每建立一次，客人姓名與電話就以明文多存一份在那台瀏覽器 localStorage（與既有專案相同性質）。

## 1. 情境
1. 待聯絡與已回報卡片都有「**帶入名單建立專案**」按鈕，**放在聯絡結果按鈕區之外**（避免看成第五種回報），旁邊固定短句「只存在這台瀏覽器」。
2. 按下 → 以名單 id **重新取該筆最新資料**（`findLead`，必要時重查）→ 用純函式 `mapLeadToProject` 建立 → 沿用 `commit()` 儲存 → **成功才**導向 `#/p/{id}/brief`；讀取或儲存失敗留在名單並提示。**不走** `openCreate`／`#project-form`。建立中按鈕停用（防連點）。
3. toast：「已建立專案（名單的聯絡結果沒有改變）」。
4. 帶入後仍須在需求總覽補齊並「確認需求」才能做策略（居家還缺精確坪數、風格、成員等）。
5. 同一瀏覽器已有此 `leadId` 的專案 → 按鈕變「**開啟專案**」；多筆時開最新一筆並 toast「這位客人有兩筆專案，開啟最近的」。離線（名單不可用）時不能建立。

## 2. 欄位對應（以名單 `answers` 為準：service、area、area_other、size、timeline、budget、name、phone、contact_time）
| 表單 | 規則 |
|---|---|
| service | 新成屋裝潢→居家裝潢設計＋屋況「新成屋」；舊屋翻新→居家＋屋況「老屋翻新」；局部裝修→居家＋裝修類型「局部翻修」（屋況留空）；商業空間→商業空間設計；其他服務或未知字串→**其他設計**，並在 `needsNote` 寫「服務（客人勾選）：其他服務」提醒改類型。不丟例外。 |
| area | 兩種形狀都要認：網頁表單 `area==="其他地區"`＋`area_other` 自由文字；聊天室／舊資料 `area` 直接是自由文字。選項別名：高雄市→高雄市、台南→台南市、台中→台中市、彰化→彰化縣、雲林→雲林縣；**嘉義不填**。自由文字與 22 縣市**逐字相同**才填 `brief.region`（「屏東縣」填、「屏東」「臺南市」不填）。對不上的原文寫進頂層 `notes`，不進 `address`、不進 `needsNote`。 |
| size | `brief.area` **留空**；`needsNote` 寫「坪數（客人勾選）：21–30 坪」（含「尚未確定」）。 |
| timeline | `needsNote` 寫「預計開始（客人勾選）：1–3 個月」。 |
| budget | 以目標類型的預算欄 `options.includes(原文)` 判斷，通過才填 `brief.budget`（居家、商空選項與表單相同）；不通過（其他設計）→ `needsNote` 寫原文。選項以程式常數為準，不在規格重抄。 |
| name | `contact`；空白→「未留姓名」。 |
| phone | `phone` 原樣。 |
| contact_time | **不寫** `brief.contactTime`；頂層 `notes` 寫「方便聯絡（客人勾選）：上午 8–12 點」。 |
| completed_at | `date`＝**Asia/Taipei 日曆日** `YYYY-MM-DD`（禁止截 UTC 字串）；`source={kind:'client', submittedAt}`（不新增 kind）；時間無效→`date` 空字串、不寫 `submittedAt`。 |
- （驗收裁決 2026-09-30）area 若**等於表單選項之一**（高雄市／台南／台中／彰化／雲林），不論有無 `area_other`，一律視為選項並套別名（與機器人 `server.js` 預填邏輯一致：值在選項內即為選項）；嘉義仍不填。只有不在選項內的自由文字才走「與 22 縣市逐字相同才填」。
- 專案名稱：姓名＋表單原文地區＋原文服務，以半形空白串接、去空段、最長 80 字，例如「王先生 台南 舊屋翻新」。
- 頂層 `notes` 另寫「由客戶名單建立」與建立當下的聯絡結果（若有）。
- **寫入分工**：`brief.needsNote`（會送策略 AI）只放坪數、開始時間、對不上的預算、其他服務提醒；**不得**含姓名、電話、地址、地區自由文字。`notes`（不送 AI）放聯絡時段、對不上的地區、來源說明。
- 頂層 `leadId`（字串）；`leadDigest`＝建立時八個答案欄位的正規化副本（不含 `_revision`、`messenger_user_id`，不存整包 `answers`）。

## 3. 名單較新提示（使用者決定要做）
- 打開有 `leadId` 的專案需求總覽、且在線時，以名單 id 查一筆，比對八欄與 `leadDigest`。
- 有差異：「名單在帶入之後改過：服務、坪數…。專案維持現在的內容。」（只列題目名稱；不自動覆寫、無「套用更新」）。
- 離線或查詢失敗：「無法核對名單是否已更新」（不可顯示成「沒有更新」）。
- 名單卡片**不**做徽章。不以 `completed_at` 判斷新舊（機器人更新時保留原送出時間）。

## 4. 來源卡與文案
- 有 `leadId` 的專案，需求來源卡顯示「來自客戶名單，送出時間 …」，並列出：已寫入欄位／寫在其他需求／寫在備註；拿掉「已送出・手動登錄」與「取消登錄」。其他設計若已有縣市，加註「類型改成居家或商業空間後，縣市會出現在欄位裡」。
- 需求總覽固定短句：「客人之後改表單，這裡不會自動更新」。
- 使用說明中「客戶送出是手動登錄」「之後串接 Messenger」等舊句同步修正。

## 5. 複製、刪除、多裝置
- 複製專案：副本清除 `leadId`、`leadDigest`。
- 刪除後按鈕回到「建立」；10 秒內復原又變「開啟」。
- 多裝置／其他瀏覽器認不出已建立（本機儲存限制）；靠「只存在這台瀏覽器」短句提醒。同電話兩筆名單＝兩筆專案，不合併。

## 6. 載入隔離（2026-09-30 事故後的強制要求）
- `projects.forEach(normalizeProject)` 改為**每筆獨立**：先 `structuredClone` 再正規化，失敗保留原物件並記錄，例外不得穿出載入。
- `leadId` 非非空字串 → 刪除該欄；`leadDigest` 非物件 → 刪除。
- 任一筆正規化失敗：本次開啟**禁止 `save()` 寫回** `genie-local-projects-v1`，畫面提示「部分資料無法讀取，請先匯出本機資料」。
- 清單與卡片渲染也要單筆隔離，壞的一筆不讓清單白屏。
- 已知風險點一併修：`Object.hasOwn(basis, …)` 遇非物件、`fieldNorm` 欄位定義不存在讀 `.type`。

## 7. 測試
- 對應：各服務（含未知）、地區兩種形狀（「屏東縣」填、「屏東」不填、`其他地區`＋`高雄市` 填、選項「台南」→台南市、自由文字「台南」不填、嘉義不填但名稱含嘉義）、坪數永不是數字（含尚未確定）、商空預算有值、其他設計預算進其他需求、`contactTime` 空白、needsNote 不含姓名電話地區原文。
- 台北日曆日：`2026-09-30T16:30:00.000Z` → `2026-10-01`；無效時間。
- `answers` 為 null／非物件：不丟例外、不建半筆。
- 連點只一筆；成功才跳頁；儲存失敗留在名單；複製後副本無 `leadId`；刪除／復原的按鈕狀態；多筆開最新。
- 名單較新：相同無提示、改服務與坪數列出題目、查詢失敗顯示無法核對。
- XSS：姓名、地區原文、其他需求含 `<img onerror>` 與 `</textarea>`。
- 手機 375／844：按鈕 ≥44px、無橫向捲動。
- 載入隔離：v3 舊資料、`leadId` 為數字／物件／空字串、一筆 basis 為數字、fieldNorm 缺欄 → 全站可開、console 無例外、原 localStorage 不被覆蓋。

## 8. 範圍外
