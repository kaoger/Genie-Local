# v8 專案雲端同步（Supabase）— 規格（定稿）

## 0. 目標與範圍
- 使用者 2026-10-01 決定：專案改存 Supabase。手機 Safari、手機主畫面 Web App（v8.1）、電腦登入後看到**同一批專案**。
- 背景：iPhone「加入主畫面」的 Web App 與 Safari 儲存空間分開。
- **只同步專案**。知識庫筆記（`genie-local-notes`）、本機顯示名稱（`genie-local-name`）維持本機，使用說明寫明。
- 範圍外：Realtime 即時協作、版本歷史、逐欄合併、附件、匯入功能、tombstone 清除排程、AI API。
- 分兩步：**Step A 資料庫**（SQL＋驗收，使用者執行）→ **Step B 前端同步**。Step A 驗收矩陣全過才開始 Step B。

## 1. 用語承諾（文案不可過度）
- 雲端是「共享儲存」，不是備份。「清瀏覽器不遺失」只限**已同步**的專案。
- 匯出（`version: 3`、四個頂層欄位，格式不變）仍是目前唯一的手動備份；免費方案沒有自動備份。

## 2. Step A：資料庫（`ops/genie-projects.sql`、`ops/queries/genie-projects-verify.sql`，放 Genie-Local）
風格沿用 `D:/Desktop/三禾聊天機器人/ops/genie-access.sql`：`begin/commit`、可重跑、具名物件、完整 schema 名、`notify pgrst, 'reload schema'`。不改其他表、不改 public schema 預設權限（不可影響機器人）。

**表 `public.genie_projects`**
- `id text primary key`、`data jsonb not null`、`version integer not null check (version > 0)`、`deleted_at timestamptz`、`created_at timestamptz not null`、`updated_at timestamptz not null`、`updated_by uuid`。
- 檢查：`jsonb_typeof(data)='object'`、`data->>'id' = id`、`data->>'name'`／`data->>'date'` 為字串（缺鍵視為不通過）、`octet_length(data::text) < 1000000`。
- trigger `BEFORE INSERT OR UPDATE`：INSERT 強制 version=1、時間＝伺服器時間、`updated_by=auth.uid()`；UPDATE 保留 id／created_at，`data` 或 `deleted_at` 真的改變才 `version = OLD.version + 1` 並更新時間與 updated_by。

**權限（只准 RPC 寫入）**
- 先對 `public, anon, authenticated` 撤銷新表的表層與欄位權限，再只給 `authenticated` 明列欄位 SELECT（`id, data, version, deleted_at, updated_at`）。直接 INSERT／UPDATE／DELETE 一律拒絕。
- RLS 開啟；SELECT policy：`exists (select 1 from public.app_admins a where a.user_id = (select auth.uid()) and a.active is true)`。**所有啟用成員共享全部專案**；SELECT 包含已軟刪除列（其他裝置才知道被刪）。
- RPC（`SECURITY DEFINER`、`set search_path = ''`、函式內每次重查 `auth.uid()` 為啟用成員；撤銷 `public, anon` 的 EXECUTE，只給 `authenticated`）：
  - `genie_save_project(p_id text, p_data jsonb, p_expected_version int)`：0＝只新增（撞 id 不覆寫→`conflict`）；正值＝只在 version 相符且未刪除時更新。回傳 `{status: saved|unchanged|conflict|not_found, version}`；不回傳衝突列內容以外的東西給非成員。
  - `genie_delete_project(p_id, p_expected_version)`、`genie_restore_project(p_id, p_expected_version)`：設／清 `deleted_at`（時間由伺服器產生），version 不符→`conflict`。一般 save 不得復活已刪列。
  - 需要多步檢查時用列鎖（`for update`）。

**驗收（`genie-projects-verify.sql`，每格標記＋最後刻意 exception 回滾，不留測試資料；輸出 `GENIE_PROJECTS_OK`）**

| 格子 | anon | 非成員 | 停用成員 | 啟用成員 |
|---|---|---|---|---|
| SELECT（含已刪） | 42501 | 0 列 | 0 列 | 可讀 |
| 直接 INSERT／UPDATE／DELETE | 42501 | 42501 | 42501 | 42501 |
| save 新增／正確版本更新 | 42501 | 42501 | 42501 | 成功，version 1／+1 |
| save 舊版本 | 42501 | 42501 | 42501 | conflict，資料不變 |
| delete／restore 正確／舊版本 | 42501 | 42501 | 42501 | 成功／conflict |
| 改 id／version／稽核欄位 | 42501 | 42501 | 42501 | 42501 |

另驗：第二位成員能讀寫第一位建立的；同 id 併發新增只一個成功；同版本併發更新只一個成功；缺鍵、id 不符、超限 JSON 被拒；無殘留 DELETE／TRUNCATE／TRIGGER 權限。Claude 另用 publishable key 實打 REST／RPC，anon 全部拒絕。

## 3. Step B：前端同步（新檔 `sync.js`＋`app.js`／`auth.js`／`leads.js`／`index.html`／`styles.css`／`tests/**`）

### 3.1 架構：本機優先＋背景同步
- `save()`／`commit()` 維持同步寫 `localStorage`（不改 async）。雲端失敗不擋本機使用。
- `commit()` 比對 backup 與變更後陣列，**只把真的改到的 id** 標成待上傳；待上傳標記寫在 `genie-sync-v1`，與專案寫入在同一次 commit 內完成（先寫專案、再寫標記；標記寫入失敗時，下次載入以「本機內容與已確認基準不同」補判為待上傳）。
- `genie-sync-v1` 每個 id 記錄：雲端 version、已確認基準的雜湊、本機修訂號、待上傳／待刪除／待復原、衝突狀態。**不寫進專案物件**，不改匯出格式。
- 上傳時捕捉「送出的快照＋修訂號」；回應只確認該修訂，期間又有編輯則保留待上傳。回應遺失時先讀回，內容相同即確認，避免假衝突。單次同步不重入；失敗退避重試。
- 同步時機：成員身分確認後、`visibilitychange` 回前景、`online`、commit 後防抖 1.5 秒（連續編輯最長 10 秒必送）、`pagehide`／被藏起時立即送（`keepalive`）、點同步狀態列重試。
- 拉雲端：明列欄位、固定排序、分頁讀完；先比 version，只套用有變的。**任何讀取失敗都不得當成雲端空清單**，畫面與 `localStorage` 維持原狀。拉下的資料走獨立入口寫本機，**不得**重新排入上傳。套用前重讀本機；待上傳的 id 跳過；期間有 commit 則作廢這次套用。本機存檔失敗就放棄套用。
- 雲端資料逐筆 clone 後 `normalizeProject`；正規化**只在記憶體**、不因此標待上傳（v7.1 規則）。壞的雲端列**跳過並隔離顯示**，不得設定 `normalizationFailed`、不得鎖住其他專案。
- 401：共用一次續期後重試；續期遇網路／5xx 保留佇列與資料，refresh token 確定無效才回登入。同步狀態獨立管理，不改 `auth.status`。
- 多分頁：用 Web Locks，**同一瀏覽器一次只有一個可寫分頁**；其他分頁唯讀並顯示「此專案已在另一個分頁開啟」，監聽 `storage` 更新畫面；可寫分頁關閉後接手。

### 3.2 合併規則
| 本機 | 雲端 | 結果 |
|---|---|---|
| 無 | 有（未刪） | 加到本機 |
| 乾淨 | 較新 | 用雲端 |
| 待上傳 | version 與本機基準相同 | 上傳 |
| 待上傳 | 較新（衝突） | **衝突提示**（§3.3），不自動覆蓋、不產生副本 |
| 新建（雲端無） | 無 | 以 expected_version=0 上傳 |
| 有 | 已刪 | 本機乾淨→移除；本機待上傳→衝突提示「另一台已刪除『○○』［仍要留下］［一起刪除］」 |
| 本機刪除墓碑 | 任何 | 墓碑 id 不得再上傳為新增 |
| 同內容不同 version | — | 只更新本機基準，不算衝突 |

### 3.3 衝突提示（使用者選：跳提示讓我選）
- 專案清單最上方一行（每個衝突一行）：「另一台有較新的『王先生』［留下這台的］［改用另一台的］」。
- 未選之前：畫面顯示**這台的版本**並標「未同步」，該筆暫停上傳；其他專案照常同步。
- 留下這台的→以雲端最新 version 為基準再上傳；改用另一台的→本機換成雲端版、清除待上傳。選完立刻清除衝突狀態，**不得重複產生衝突**。
- 永遠只有一筆專案，不產生衝突副本。

### 3.4 刪除與 10 秒復原
- 刪除：同一次 `save()` 寫入本機墓碑（含預期 version、復原所需內容、期限）。**10 秒內不打網路**；逾時或頁面被藏起才送 `genie_delete_project`。
- 10 秒以「使用者何時按復原」判定：未送出→撤銷墓碑；送出中→記錄復原意圖，拿到刪除 version 後送 restore；已完成→`genie_restore_project`。支援離線。保留現有連續刪除延長期限的行為；同步提示不可蓋掉復原按鈕。
- 重新載入後已刪專案不得復活。使用說明：「刪除後從清單消失；資料庫仍保留，需徹底移除請管理者處理。」

### 3.5 第一次上傳與示範資料
- 升級後第一次以成員同步、且雲端清單**完整讀取成功**後：本機非示範專案逐筆上傳（逐筆記錄進度，部分失敗可續傳）；完成 toast「已上傳 N 筆本機專案到雲端」。上傳前不另加確認頁。
- 示範：**沒改過**的 `sample-*` 不上傳；**改過的** `sample-*` 先換成新的 `crypto.randomUUID()`（同時更新 `data.id`）再上傳。
- 新裝置：雲端首次讀取完成前不 `save()`、不寫入種子；雲端有任何專案（含已刪）就不顯示示範；雲端完全沒有列時才顯示 8 筆示範。
- 名單建立專案：上傳前若雲端已有相同 `leadId` 的未刪除專案，改為打開那筆並提示「這位客人已有專案」。

### 3.6 登出與停用（使用者選：清掉，先確認都上傳了）
- 按登出：先嘗試送出所有待上傳；仍有未上傳時顯示「還有 N 筆沒上傳，請連上網路再登出」並提供［匯出後登出］［取消］；全部上傳後清除這台的專案快取與 `genie-sync-v1`，再登出。
- 查到停用成員（`denied`）：停止同步並清除專案快取與 `genie-sync-v1`（停用者不可再上傳）。
- 離線狀態（`offline`）不清。登出時忽略登出前請求的晚到回應。筆記與記住的信箱保留。

### 3.7 畫面
- 同步狀態列放**專案清單最上方**一行：「已同步」「同步中…」「N 筆待上傳（離線）」「同步失敗，點此重試」「N 筆無法讀取（已隔離）」。失敗不擋使用。不另做「立即同步」按鈕。
- 背景拉到新版而該專案抽屜正開著：不重畫吃掉草稿；顯示「另一台已更新這個專案」，儲存時依 §3.2 規則處理。同步本身不得改變六步完成狀態。
- 更新文案：`leads.js` 的「只存在這台瀏覽器」、個人設定、使用說明（雲端共享＋本機快取、只同步專案、匯出是手動備份、表單按儲存後才會同步）。所有雲端字串經 `esc()`。

## 5. 預估
- Step A：Codex 3–4 小時；使用者執行 SQL 約 10 分鐘。
- Step B：Codex 13–20 小時；實機驗收約 30 分鐘。合計約 2–3 個工作天。

## 6. 兩方採納紀錄
- **使用者決定**：專案改存 Supabase；衝突跳提示二選一（不產生副本）；登出清本機專案（先確認都上傳）。
- **一致**：本機優先＋背景同步、`commit` 維持同步、單一 jsonb、RPC＋trigger、軟刪除、讀取失敗不當空庫、正規化不回寫、示範改過換 UUID、匯出格式不變、筆記不同步、驗收矩陣必過。
- **Grok 採納**：`authenticated` 也要先撤銷全部權限、RPC 撤銷 public 執行權、墓碑防復活、10 秒內不打網路、壞雲端列不鎖存檔、新裝置下載前不寫種子、相同 leadId 去重、`pagehide` 立即送、狀態列放清單上方、刪掉「立即同步」鈕、停用時清快取。
- **Codex 採納**：只准 RPC 寫入與驗收矩陣、私有權限細節、送出快照＋修訂號、回應遺失先讀回、合併真值表、分頁讀取、Web Locks 單一可寫分頁、401 續期分流、背景更新不吃草稿、10 秒以按復原時間判定、用語不過度承諾、工時 2–3 天。
- **未採納**：自動衝突副本（Codex，使用者選提示）；登出一律保留快取（Codex，使用者選清除）。
