# Genie-Local v6.1｜潛在客戶工作台

使用新版 Chrome 或 Edge 開啟網站並登入後，才能使用整個工作台。純前端、免建置；字型使用本機 assets。登入使用唯一的外部套件 supabase-js，檔案由本站供應。

## 客戶名單（v5）

全站需登入並通過啟用成員檢查。客戶名單讀取雲端資料；本機專案保存在這台瀏覽器。已確認過的同一成員在暫時離線時可繼續使用本機功能；恢復連線後會重新查驗。共用裝置用完請登出。忘記密碼請聯絡管理者重設。

客戶名單以「待聯絡／已回報」標籤切換，一次顯示一區；數字是資料庫總筆數。已回報可依聯絡結果篩選，選中的晶片顯示篩選筆數。頁內重新整理及切回前景會保留目前標籤與晶片，整頁重載則回到「待聯絡／全部」。離線時筆數顯示「—」。

名單卡片可按「帶入名單建立專案」，以最新名單資料在這台瀏覽器建立本機專案；聯絡結果不會改變。若這台瀏覽器已有同一筆名單的專案，按鈕改成「開啟專案」，多筆時開最近建立的一筆。建立後要在需求總覽補齊資料並「確認需求」才能進行策略企劃。客人後續修改表單時，需求總覽會提示差異，但不會自動覆寫專案；離線時無法建立或核對。其他瀏覽器與裝置的本機專案不會同步。姓名、電話和備註會以明文保存在這台瀏覽器的 localStorage。

- `vendor/supabase.js`：Supabase 官方 supabase-js **2.117.2** UMD，來源 `https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2.117.2/dist/umd/supabase.js`，SHA-256 `59d39487c3589843b410322d8a3d562ce022aba1e5ccb16898ef3fb2a0da2ecd`。
- 更新方式：選定官方版本後下載對應 UMD 到 `vendor/supabase.js`，核對來源與 SHA-256，更新這裡的版本、來源與雜湊，再跑語法與 Playwright 測試。不要改成從 CDN 載入。
- `config.js` 只放 Supabase 網址和公開的 publishable key；它不是 secret key，只作為請求的 `apikey`。權限仍由登入、資料庫 GRANT 與 RLS 控制。secret key 不得放進前端。
- 新增成員：由管理者建立 Supabase Auth 帳號，並依 VPS-message repo 的 `ops/genie-add-member.sql` 將使用者加入 `public.app_admins`。

## 六步驟流程

每一步都能隨時打開查看，必要條件只限制生成、確認與標記完成。

1. **需求總覽**：選擇手動建立、會議記錄整理或客戶填寫。補齊「必填」欄位，再按「確認需求」。坪數須大於 0。
2. **策略企劃**：確認需求後複製 AI 指令，貼到自己的 AI App；複製整段回覆並貼回網站，預覽五欄與警告後選「設成目前版」或「只留下比較」。比較版最多三份，可選來源、改用或刪除。只有目前版可編輯並作為「標記完成」的依據；示範草稿仍可使用，替換目前版會保留上一版供對照。
3. **視覺發想**：查看會帶入的需求，在其他工具完成後回來標記完成，也可選「本案不採用」。
4. **3D 建模**：同樣支援外部完成與不採用。品牌、包裝、網站設計在本版不提供 3D。
5. **業務估價**：隨時可編輯明細、稅別、有效期限與報價範圍。需求須確認、至少一筆有效明細、所有有內容的列都完整，才能標記完成。
6. **提案簡報**：預覽專案概要、策略、採用的視覺／3D 狀態及估價。引用的步驟都完成後，才能標記完成。

生成不等於完成，客戶送出也不等於需求已確認。

## 狀態與更新

| 狀態 | 意義 |
| --- | --- |
| 缺資料 | 主要動作缺少必要欄位或前置確認 |
| 可開始 | 可開始編輯或生成，尚未人工確認 |
| 已完成 | 人工確認過，完成依據沒有改變，且前置步驟目前都已完成 |
| 需更新 | 有完成紀錄或策略成果，但依據已改變，或前置步驟尚未完成 |
| 不適用 | 本版不提供，或本案不採用 |

完成時保存依據快照，使用鍵排序後的 JSON 比對。修改需求會列出受影響的欄位；修改電話、電子信箱與備註不影響步驟狀態，修改專案名稱或聯絡人會讓提案需更新。可用「取消確認／取消完成」移除該步驟的完成紀錄。

前置步驟未完成時，下游已有完成紀錄的步驟會連鎖變成「需更新」。若自身依據沒變，會顯示「上游需更新」；前置恢復完成後會自動恢復。單純取消再確認相同內容，不需要重新標記所有下游。

視覺／3D 的依據是畫面「會帶入的資料」及策略生成版本；重新生成策略會讓已完成的視覺／3D 與提案需更新。提案記錄專案名稱、聯絡人、類型及引用步驟的內容依據，不使用完成時間。需求尚未確認時，策略頁提供「前往需求總覽」。

v4 已保存的視覺／3D 與提案依據格式不同，升級後需依新依據檢查並重新標記完成；不會自動改寫舊完成紀錄。

## 需求來源與完整表單

- 會議記錄可貼文字及參考檔名；只保存文字與檔名，不保存檔案，不自動填欄位或確認需求。按「對照記錄填寫欄位」會先儲存記錄，再開啟有可收合記錄的側邊表單。
- 從客戶名單帶入的專案會顯示表單送出時間及欄位去向，不提供取消登錄。一般手動建立的「客戶填寫」來源仍可自行記錄送出時間。
- 點欄位或「編輯全部資料」開啟表單。可用 Ctrl＋S 儲存；有未儲存修改時關閉會提醒。
- 居家、商業／展覽、其他設計各有對應欄位。切換類型保留未儲存的草稿，舊預算或施作選項不在新選項內時仍保留。
- 儲存後顯示變更欄位數與新變成「需更新」的步驟。儲存失敗保留表單及草稿，不套用變更。

## 估價

- 空間類型預設室內設計費、3D 圖與施工圖、工程監造；其他類型預設設計提案、修改與完稿。沒有編輯時不寫入預設列。
- 室內設計費預設沿用需求坪數。修改數量後改為自訂計價坪數，不反向修改需求；可按「改回沿用」。即使使用自訂數量，需求坪數改變仍會讓已完成估價需更新，提醒覆核。
- 輸入時即時試算，離開欄位時儲存，不整頁重繪。新增／刪除列與改回沿用會重繪明細。
- 未稅另加 5% 營業稅；含稅金額拆分未稅小計與內含稅額，不重複加稅。金額顯示至小數點後兩位。
- 客戶預算只顯示原需求文字，不與合計比較。預設列若不使用，請刪除，避免未填單價的列阻擋完成。

## 清單與本機資料

- 每頁 8 筆，顯示需求來源及第一個尚未完成、尚未排除的步驟；點步驟可直接前往。寬度 900px 以下改用卡片，可點整張卡進入專案，並保留全選、批次刪除與復原。
- 新增專案預設居家裝潢設計，建立後進入需求總覽。複製保留欄位、需求、估價與不採用設定，清除完成紀錄、兩版策略、這次指令、比較清單及名單關聯，來源改為手動建立。
- 單筆或勾選批次刪除有確認對話框，10 秒內可復原整批並還原順序；在復原期限內連續刪除會合併為可復原的批次。
- 所有專案變更先保存，成功後才套用畫面；失敗回復記憶體資料。知識庫與個人設定也在儲存成功後才關閉。
- 使用原 localStorage 鍵 `genie-local-projects-v1`。舊資料缺少的結構會補齊，未註明來源的舊資料顯示「未註明」，舊 `done` 保留但不參與新狀態。
- 全新瀏覽器提供 8 筆示範資料；另有不計入筆數的「範例」展示列。
- 左側對話圖示可匯出 JSON 備份（`version: 3`），包括專案、工作筆記與顯示名稱。備份保留原始資料字串，HTML 顯示才使用 `esc()`，避免改變資料內容。

本機專案只存在目前瀏覽器的 localStorage。清除瀏覽器資料會移除記錄，不同瀏覽器／網址的資料不會同步。登出不會刪除本機資料；它們仍以明文存在瀏覽器中。客戶名單資料來自 Supabase 雲端資料庫（Messenger 表單）。專案存資料庫、AI 串接、JSON 匯入、正式提案匯出、視覺／3D 內容生成與完整版本歷史尚未提供。

## 調整欄位

欄位集中在 `app.js` 頂部「表單欄位定義」。卡片、表單與依據快照共用設定：

- 區塊 `req:true`：區塊欄位屬於需求；聯絡資訊、備註不設定。
- 欄位 `top:true`：存在專案本身。
- 欄位 `ai:true`：確認需求、生成策略需要的必填欄位。
- 欄位 `est:true`：估價引用的需求，修改後會影響已完成估價。
- 欄位 `type`：text / email / tel / date / month / number / select / textarea / chips / layout。
- `multi:true`：chips 多選；`wide:true`：欄位跨欄。

- `index.html`：清單、導覽與對話框結構。
- `app.js`：欄位、資料轉換、完成依據、頁面、估價與儲存互動。
- `styles.css`：黑白灰版面、綠色完成、琥珀更新及手機排版。

語法檢查：`node --check app.js`。

## 自動化測試

測試使用 `@playwright/test` 1.63.0（僅開發相依套件），產品仍可直接開啟，免建置。需要 Node.js、npm、Python，以及已安裝的 Playwright Chromium。

```sh
npm install
npx playwright test
```

若 Windows PowerShell 的執行政策封鎖 `npm.ps1`／`npx.ps1`，使用對應的 `npm.cmd install`／`npx.cmd playwright test`，不需修改執行政策。

官方執行器會以 headless Chromium 執行測試，並透過 `playwright.config.js` 的 `webServer` 自動啟動 `http://127.0.0.1:4173`；該網址已有伺服器時會沿用，請確保服務的是本專案。每個案例使用獨立瀏覽器環境並清空 localStorage，不影響平常瀏覽器中的資料。

`tests/list.spec.js`、`brief.spec.js`、`flow.spec.js`、`estimate.spec.js`、`layout.spec.js` 涵蓋清單、需求表單、流程狀態連動、估價及 375×812 手機版面，共用操作集中在 `tests/helpers.js`。依 `docs/測試規格.md` 對應驗收 1～19；驗收 20 的個資掃描由 Claude 在推送前另行處理，不寫入測試。

瀏覽器測試只使用 `npx playwright test`，不自行啟動瀏覽器、不開除錯埠、不使用 CDP／Puppeteer 或 TEMP 腳本。測試若揭露產品問題，保留失敗結果及重現步驟，由 Claude 複查裁決。

## v6 策略企劃 AI 草稿

在「策略企劃」先預覽遮罩後的完整指令，再複製到自己的 ChatGPT、Claude 或 Gemini。把 AI App 複製的完整回答貼回網站，檢查五欄預覽與警告後，選「設成目前版」或先點來源並選「只留下比較」。比較清單最多三份，第四份須確認才會擠掉最舊一份；可把比較版改成目前版或刪除。只留下比較不改目前版及步驟狀態。指令只包含指定需求欄位，自由文字中的電話與信箱會盡力遮罩；複製前仍須人工確認。這次指令與策略草稿儲存在本機專案資料。

`tests/fixtures/strategy-real-chatgpt-codeblock.txt`、`strategy-real-gemini.txt`、`strategy-real-claude.txt` 是使用者提供的三家 AI 真實回答（示範專案假資料），自動化測試逐欄比對全文。原有 `strategy-chatgpt.txt`、`strategy-claude.txt`、`strategy-gemini.txt` 仍是自擬的格式測試樣本。
